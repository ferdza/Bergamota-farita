# GPU + power: our code vs Linux and sibling XNU ports (2026-11-12)

Tags: VERIFIED = read in a file this session; INFERRED/RECALLED = reasoning or memory, not re-read. No GPL code copied; register facts only.
Ours = series-patched tree (patches up to 0278; 0279/0280 read from the patch files): `scratchpad/full/bsd/dev/sweet_a630.c` (abbrev. A630) and `iokit/Kernel/arm/SweetAdreno.cpp`.
Linux = `scratchpad/lx/` (a6xx_gmu.c, a6xx_gpu.c, a6xx_hfi.c, arm-smmu-qcom.c, msm_iommu.c). Already handled, not repeated: VBIF halt (0280), SMMU TLB flush while slumbered (0279).
Not done: root cause of the ~460-580 s freeze is NOT identified; everything below is a difference, not a proven cause.

## What each sibling does (VERIFIED unless stated)

- edi194_ios-fajita (OnePlus 6T, same SoC; same lineage as our driver): NOTES-FAJITA.md:1075-1140 records a freeze when S2CR was written without a VALID SMR (0111), fixed by `smmu_impl_init` + exact SMRs (:1204-1350). Slumber: power counter off, SPTPRAC off, BOOT_SLUMBER_OPTION 1, OOB, state 0xf (:1466, :1684); ack for the slumber OOB did not arrive. No bus halt, no wait-for-idle, no RSC stop. Also: a read of the low memory bank after GPU power-on froze the boot (:1146). No long-uptime freeze reported (GPU kept up, teardown skipped, :1868).
- LakoMoor_ios-beryllium (really Apollo/SM8250, a650): 0102 patch teardown order = GBIF halt (client then arb, then release), OOB clear, slumber, CM3 reset, RSCC asleep check, SMMU SMR/S2CR back to FAULT and SCTLR=0, CX collapse. NOTES.md:621: clean teardown boots do not hang; a hang came from a blind yielding SCM call. Matches Linux order better than ours.
- oosexgang_hackios-xnu-kernel (SM7325 a660): hakios.adreno.c:3039-3139 `gpu_block_stop`: bus halt, OOB, HFI PREPARE_SLUMBER, CX busy poll, CM3 reset, GX off if the GMU did not, RSC sleep and wait for bit16, SMMU contexts off, CX collapse; RSC wake only if asleep (:1941); RSC/PDC program only if not present (:2026). `core_stuck` keeps the bus halt asserted. Closest to Linux; shows the three things we lack (#1, #2, #6).
- keyfan_UniXNU-enchilada-bringup (OnePlus 6, SDM845): AdrenoGmuBootV1.c replays the Linux boot sequence; only grep-level look, no teardown/slumber code found (INFERRED: boot-only). MakrSas_ios-topaz, joranv1_ios-sailfish: no GMU slumber/halt code found by grep (topaz is a610 without GMU: INFERRED).
- None of the siblings reports a ~8 min screen-on SoC freeze; none runs repeated idle slumber/wake cycles like ours, so there is no sibling evidence either way.
