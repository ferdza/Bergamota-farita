## 3. CPU frequency, governor, idle, "little cluster at 100%"

### 3.1 Measurement checked (VERIFIED)

`cf_cluster_load` (T:bsd/dev/sweet_cpufreq.c:434-452, v1) and `cf_cluster_busy` (:557-585, v2) take, per CPU, `idle` from `sweet_processor_idle_time()` (T:osfmk/kern/processor.c:754-770) = `recount_processor_usage` (T:osfmk/kern/recount.c:1241-1257), which adds the *still running* idle interval (`mach_absolute_time() - stamp`) when the CPU is currently idle. `processor_idle()` (T:osfmk/kern/sched_prim.c:7217-7226) sets the idle stamp, and `machine_idle`/WFI and interrupt handling inside it count as idle. So an idle CPU reads ~0% busy, a CPU that never reaches `processor_idle()` reads 100%. Window start/end skew only makes an idle CPU look *less* busy (`didle >= wall -> 0`). Conclusion: **the 100% is not a metering artefact; at least one A55 really is not idle.** The cluster value is the busiest CPU on purpose (:432, 597).
